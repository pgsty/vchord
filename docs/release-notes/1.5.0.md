vchord 1.5.0 supports PostgreSQL 15–19 on x86_64 and aarch64.

- Ordered RQ scans with filter keys stream their initial probes and expand as the caller requests more rows. Distances can decrease between refill rounds. Half-precision L2 search uses FP16 differences where supported and avoids rereading centroids during routing.
- Sphere scans recheck graph, half-precision, inner-product, cosine, quantized and split-vector candidates against the heap predicate. RQ can accept a single f32 L2 sphere directly when its final distance uses the same whole-vector reduction as the SQL operator and all filter keys are exact. A NULL sphere ends the scan immediately.
- Ordered scans on nullable vectors preserve rows selected by `IS DISTINCT FROM` and `IS NOT DISTINCT FROM`. The planner recognizes validated nonnull attributes. When a runtime ordering key is NULL, scans stream visible heap rows and resolve heap-only tuples to their HOT roots.
- RQ prefiltering evaluates eligible nonvolatile subqueries during search. Subplans with aggregates stay in the executor so their transition functions run once per required evaluation.
- Graph insertion publishes a new vector page and its incoming link in one WAL record. An unchanged backlink requires only a shared identity check. VACUUM uses bounded local repair to reconnect live regions across deleted bridge vertices.
- RQ VACUUM returns each compacted list’s retired pages to persistent free space after publishing the list. Exclusive builds reuse retired pages across lists. Unkeyed list compaction streams rows and uses the appendable tape’s tail hint.
- CPU-bound graph and RQ builds can use parallel workers on small TOAST-backed heaps. Temporary tables and parallel-unsafe index expressions or predicates build serially. Keyed RQ compaction shares its sort budget across the leader and the workers actually launched.

Install the library and SQL files for your PostgreSQL major, restart PostgreSQL, and run `ALTER EXTENSION vchord UPDATE TO '1.5.0';` in each database. Version 1.5.0 reads 1.4.0 indexes in place and uses the same SQL objects and on-disk formats. A database on 1.3.0 can upgrade through the supplied 1.4.0 script.

If a graph lost an entire region following a previous VACUUM, rebuild the affected index with `REINDEX INDEX CONCURRENTLY index_name;` to restore links that the older VACUUM already removed.
