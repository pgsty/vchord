vchord 1.4.0 adds filter key indexes and read-ahead improvements, updates pgrx to 0.20.1, and supports PostgreSQL 15–19 on `x86_64` and `aarch64`.

- Add equality, range, and NULL conditions on RQ filter key columns, with separate operator classes for hashed keys. Enum ranges follow PostgreSQL enum order, including domains and values inserted with `ALTER TYPE ... ADD VALUE ... BEFORE/AFTER`. Index pushdown of `= ANY(...)` filter key conditions on ordered vector scans requires PostgreSQL 17+.
- Extend searches with a pushed-down filter key beyond the initial IVF probes, streaming batches lazily as rows are consumed without spilling to sort. `vchordrq.max_probes` limits the total leaf lists visited during expansion; the initial probes are always honored, and the default `-1` allows all lists.
- Stream ordered refills directly without buffering the full result set. Each visited list applies the query sphere independently. For a single bounding sphere, clear interior matches skip PostgreSQL's recheck (avoiding TOAST detoasting on high-dimensional vectors) while boundary candidates still reach strict recheck; `NULL` sphere predicates short-circuit immediately without scanning.
- Center residual inner-product estimates in leaf lists on the query's projection onto the centroid. Cosine normalization rescales finite nonzero vectors in a single pass. Half-precision L2 routing and index reranking use FP16 differences on supported hardware with scaled residual bounds and an overflow fallback, avoiding synchronous centroid page re-reads.
- Compact an RQ list while readers use its current pages, with dedicated exclusive-build and O(1)-memory unkeyed streaming fast paths and appendable-first no-op `VACUUM` checks.
- Restore CPU-bound parallel index build workers for `vchordrq` and `vchordg` on TOASTed and medium tables whose main heap stays under `min_parallel_table_scan_size`, while preserving PostgreSQL's parallel-safety checks.
- Reduce `vchordg` write/WAL amplification and `VACUUM` cost: populate newly extended vector pages before linking, skip lock/WAL on no-op backlinks, skip single-neighbor retry exhaustion instead of aborting builds, bound local repair depth with an O(m) live-vertex fallback for isolated start vertices, and reclaim all deleted vertices without full-graph reachability sweeps.
- Keep `vchordrq.prefilter` enabled for non-volatile `SubPlan` filters (`EXISTS` / `IN (SELECT ...)`) while keeping volatile subplans in the executor.
- Parse `vchordrq` and `vchordg` index options with `toml` 1.2.2, which includes a fix for a backend crash on malformed options. The query recorder uses `rusqlite` 0.43.0 with bundled SQLite 3.54.1. If SQLite detects a corrupt sampling database or an invalid file header on open, sampling can resume with a fresh file on the next request.
- Preserve PostgreSQL's old-snapshot protection when any parallel RQ or graph build participant encounters a broken HOT chain. RQ and graph indexes omit NULL vectors. The planner keeps vector index plans on `NOT NULL` columns and `IS DISTINCT FROM` filters, falls back to streaming sequential scan for literal `ORDER BY v <-> NULL`, and streams visible heap rows lazily in O(1) memory when a parameterized ordering key evaluates to `NULL` at execution. PostgreSQL can sort additional distance keys after the first.
- Improve SIMD kernels, list reading, table prefetch, and reranking. On PostgreSQL 17+, `vchordrq.io_search` defaults to `mixed`; reranking defaults to `prefetch_buffer`.
- Report `pg_stat_user_indexes.idx_scan` counts across PostgreSQL 15–19 and `Index Searches` in `EXPLAIN ANALYZE` on PostgreSQL 18+, pass read-only scan hints on PostgreSQL 19, and reject invalid indexes in `vchordrq_prewarm` and `vchordg_prewarm` before reading pages.
- Add PostgreSQL 19 to the test and Linux package matrices (`x86_64` and `aarch64`). The release workflow stages the DEB and ZIP packages from all ten builds, verifies their checksums, and uploads to an existing draft release. Retried uploads skip assets with matching SHA-256 digests.
- Require Rust 1.100.0 or later and matching Clang, libclang, and LLVM tools.

Install the matching package, restart PostgreSQL, and run `ALTER EXTENSION vchord UPDATE;` in each database. The upgrade adds filter key functions and operator classes. Existing 1.3.0 ordinary RQ indexes and newly built single-column RQ indexes use format `1001`. New RQ indexes with filter key columns use format `1003`. To roll back, first drop or replace keyed indexes under 1.4.0, then restore a catalog or backup compatible with 1.3.0. A package downgrade alone leaves the 1.4.0 SQL catalog in place.

The parallel build fix protects transactions whose snapshots predate an affected build. Once those transactions end, later snapshots can use the built index normally. Existing indexes do not need a blanket rebuild for this fix.

Sphere scans remain approximate in both access methods. The graph traversal can encounter a matching row after its first out-of-radius candidate. RQ candidate pruning can skip a match even in a visited list. Applications that require every matching row should verify a sequential scan with `EXPLAIN`. See [issue #29](https://github.com/pgsty/vchord/issues/29).

PostgreSQL 14 is no longer supported by pgrx. Upgrade PostgreSQL before installing this release. Earlier extension releases may have additional migration requirements; consult the project migration guide.
