vchord 1.4.0 adds filter key indexes and read-ahead improvements, updates pgrx to 0.20.0, and supports PostgreSQL 15–19 on `x86_64` and `aarch64`.

- Add equality, range, and NULL conditions on RQ filter key columns, with separate operator classes for hashed keys. Enum ranges follow PostgreSQL enum order, including domains and values inserted with `ALTER TYPE ... ADD VALUE ... BEFORE/AFTER`. Index pushdown of `= ANY(...)` filter key conditions on ordered vector scans requires PostgreSQL 17+.
- Extend searches with a pushed-down filter key beyond the initial IVF probes. `vchordrq.max_probes` limits the total leaf lists visited during expansion. The initial probes are always honored, and the default `-1` allows all lists. In an ordered search that can expand, RQ reranks one leaf at a time and uses a PostgreSQL sort across all eligible candidates. Sorting on the original rerank distance preserves near ties before the L2 square root or cosine offset rounds them together. The sort can spill at `work_mem` and increases first-row latency even with a small `LIMIT`. Single-round searches retain streaming reranking. A sphere around the query vector applies independently to every visited list, with a heap recheck of the strict radius.
- Center residual inner-product estimates in leaf lists on the query's projection onto the centroid. Cosine normalization rescales finite nonzero vectors with extreme magnitudes. Half-precision L2 routing uses FP16 differences on supported hardware with an overflow fallback, while final reranking and residual bounds use FP32 differences.
- Compact an RQ list while readers use its current pages. Maintenance briefly locks the list's jump page exclusively to publish the new tapes and account for inserts that arrived during compaction.
- Preserve PostgreSQL's old-snapshot protection when any parallel RQ or graph build participant encounters a broken HOT chain. Queries requiring a NULL primary vector use a heap or other applicable path. With a NULL ordering parameter at execution, both AMs return visible heap rows subject to the partial index predicate and query conditions. Non-NULL parameters retain ANN scans. PostgreSQL can sort additional distance keys after the first.
- Improve SIMD kernels, list reading, table prefetch, and reranking. On PostgreSQL 17+, `vchordrq.io_search` defaults to `mixed`; reranking defaults to `prefetch_buffer`.
- Report `pg_stat_user_indexes.idx_scan` counts across PostgreSQL 15–19 and `Index Searches` in `EXPLAIN ANALYZE` on PostgreSQL 18+, pass read-only scan hints on PostgreSQL 19, and reject invalid indexes in `vchordrq_prewarm` and `vchordg_prewarm` before reading pages.
- Add PostgreSQL 19 to the test and Linux package matrices (`x86_64` and `aarch64`). The release workflow stages the DEB and ZIP packages from all ten builds, verifies their checksums, and uploads to an existing draft release. Retried uploads skip assets with matching SHA-256 digests.
- Require Rust 1.99.1 or later and matching Clang, libclang, and LLVM tools.

Install the matching package, restart PostgreSQL, and run `ALTER EXTENSION vchord UPDATE;` in each database. The upgrade adds filter key functions and operator classes. Existing 1.3.0 ordinary RQ indexes and newly built single-column RQ indexes use format `1001`. New RQ indexes with filter key columns use format `1003`. To roll back, first drop or replace keyed indexes under 1.4.0, then restore a catalog or backup compatible with 1.3.0. A package downgrade alone leaves the 1.4.0 SQL catalog in place.

The parallel build fix protects transactions whose snapshots predate an affected build. Once those transactions end, later snapshots can use the built index normally. Existing indexes do not need a blanket rebuild for this fix.

PostgreSQL 14 is no longer supported by pgrx. Upgrade PostgreSQL before installing this release. Earlier extension releases may have additional migration requirements; consult the project migration guide.
